# 启动器（Launcher）：原生窗口入口 + Fluent 2 配置页

> 状态：蓝图已冻结（2026-10-18），按 `.scratch/launcher/issues/` 的棒次实施。
> 术语以 `AGENTS.md` 为准（槽位 / 覆盖层 / 条目 / 插件目录 / 拔盘守护），本文不另造词。

## 问题

这个包的日常入口现在是 `dsh-ui.cmd`：双击 → 控制台黑窗 → 浏览器打开 `127.0.0.1` 页面。
能用，但有三个真实的别扭：

1. **不像应用**：黑窗是"服务活着"的唯一信号，关掉它或关掉标签页，用户无法判断 dsh 是停了还是还在后台跑
   （事实上 dsh 是 `ui-server` 的子进程，父进程退出后它继续活着）。
2. **配置页住在浏览器的共享进程里**：扩展、历史、密码管理器、别的标签页共用同一个进程。
   页面本身不回显密钥、口令只存服务内存，但"把安全管理界面托管在用户日常冲浪的进程里"和这种便携包的定位不匹配。
3. **每次都要过一道令牌**：`?token=` 的地址必须从黑窗里点开或粘贴，地址栏里留一条带令牌的历史记录。

## 方案

新增一个**启动器**（原生窗口），让"双击图标 → 看到界面"成为唯一动作：

- 双击 `dsh-to-go.exe` → 启动器起本地服务（隐藏控制台）、抓到本次运行的令牌、开一个原生窗口，
  窗口里是配置页；地址栏不存在，窗口标题里也不出现令牌。
- 窗口外观与配置页统一到 **Fluent 2**（Fluent UI Web Components v3，本地内联、零外链）。
- 关窗时问一次"dsh 要不要一起停"（默认停），未解锁时只关窗口并明确告知 dsh 仍在运行。
- 极少数缺 .NET / WebView2 的机器：**不报错退出**，回退到原来的 `dsh-ui.cmd` 浏览器路径并说明原因。

## 用户故事

1. 作为一个插上 U 盘就要干活的人，我想双击一个 exe 就看到界面，而不是先看黑窗再找浏览器，这样我不用记两条命令。
2. 作为同一个用户，我想窗口里没有地址栏、没有浏览器工具栏，这样它看起来是个应用而不是一个网页。
3. 作为同一个用户，我想关窗时被问一次"dsh 要不要一起停"，这样我不会留下一个自己不知道还在跑的进程。
4. 作为同一个用户，我想在没输口令就关窗时被告知"dsh 仍在运行"，这样下次打开时知道发生了什么。
5. 作为同一个用户，我想再次双击 exe 时只是把已有窗口叫到前台，而不是起第二个服务、撞端口。
6. 作为同一个用户，我想启动器自己挑一个空闲端口，这样我同时开着浏览器里的配置页也不会互相挤掉。
7. 作为同一个用户，我想在没有 `runtime\node` 的新盘上双击 exe 也能看到引导（并一键开始构建），而不是看到一个闪退的黑窗。
8. 作为同一个用户，我想在极少数没有 WebView2 的机器上自动退回浏览器，这样包不会彻底打不开。
9. 作为一个关心密钥的人，我想 UI 里任何地方都看不到已存密钥的明文，只有长度占位，这样我截屏/共享屏幕不会泄。
10. 作为一个关心密钥的人，我想启动器不保存任何凭据（没有"记住口令"），这样换人用这块盘时口令仍然有效。
11. 作为一个关心密钥的人，我想启动器不把令牌写进 URL、历史、窗口标题或日志，这样日志可以安心发给别人看。
12. 作为一个关心密钥的人，我想 WebView2 的开发者工具、右键菜单、浏览器快捷键都被关掉，这样窗口不能被拿来当调试器读页面内存。
13. 作为一个关心密钥的人，我想 WebView2 的密码保存与自动填充被关掉，这样口令不会被浏览器记下来。
14. 作为一个关心密钥的人，我想窗口只能停在 127.0.0.1 的本服务上（外链导航被拦），这样页面不会被导航到别处。
15. 作为一个关心密钥的人，我想 WebView2 的用户数据目录落在盘上，这样宿主家目录里不留痕迹。
16. 作为这个项目的维护者，我想配置页仍然是单文件 `ui/app.html`、零外链，这样离线盘不会因为 CDN 挂掉而白屏。
17. 作为维护者，我想 Fluent 组件是构建时内联进去的，这样我不用在盘上多带一堆 JS 文件。
18. 作为维护者，我想 `build.cmd` 顺便把启动器编译出来（用系统自带的 `csc.exe`），这样构建机不需要装 .NET SDK。
19. 作为维护者，我想 WebView2 的 DLL 存在仓库里，这样离线克隆也能构建。
20. 作为维护者，我想五个分区（概览 / 站点和模型 / 升级 / 诊断 / 插件）都迁到 Fluent 组件，而不是一半新一半旧。
21. 作为维护者，我想启动器的验收是"真起 exe 并检查窗口/日志/数据目录"，而不是"编译成功"。
22. 作为维护者，我想有脚本能扫出"日志/URL/命令行里出现密钥或口令"的回归，这样红线不是靠自觉。
23. 作为维护者，我想 `AGENTS.md`、`README.md`、`docs/ROADMAP.md` 的入口说明同步更新，这样下一个人不会照着旧文档找命令行。
24. 作为维护者，我想旧的 `dsh-ui.cmd` 仍然可用，这样启动器出问题时有一条已知的退路。
25. 作为使用者，我想窗口里的标题栏、按钮、输入框、通知都遵循同一套 Fluent 视觉（圆角、层次、动效），这样界面看起来是"做过的"。

## 实现决策

### 外壳

- WinForms + WebView2，C#，目标 .NET Framework 4.8（最低 4.6.2），用系统 `csc.exe` 编译。
  理由与代价见 `docs/adr/0001-launcher-shell.md`。
- WebView2 SDK 钉 **1.0.2903.40（net462）**，只用默认环境 `EnsureCoreWebView2Async(null)`，
  数据目录用 `CreationProperties.UserDataFolder` 指到盘上；最新 SDK 在本机运行时会抛 `E_NOINTERFACE`（实测）。
- 启动器负责：找空闲端口 → 起 `tools/ui-server.js --no-open --port <p>`（隐藏控制台、捕获 stdout）→
  从 stdout 抓令牌 → 轮询本服务就绪 → 开窗 → 退出时收拾子进程。
- **令牌不进 URL**：启动器通过 `window.chrome.webview.postMessage` 把令牌交给页面；页面**优先**读
  `location.search` 里的 `token`（浏览器回退路径仍然成立），读不到再向宿主请求。
- 单实例：命名互斥体；第二个实例把已有窗口激活到前台（不新起服务）。
- 端口：从 3181 起向上找第一个空闲端口，避免和浏览器里开着的实例撞。
- 关窗语义：已解锁 → 弹一次选择（默认"停掉 dsh"，可勾"后台继续"）；未解锁 → 只关窗口，并提示 dsh 仍在运行。
- 缺 `runtime\node`：窗口内显示引导页（Fluent），可一键调用构建流程。
- 缺 .NET / WebView2：不弹窗报错，直接回退 `dsh-ui.cmd`，并在控制台/消息文件里说明原因。

### 密钥红线（验收口径）

1. API key 与口令绝不进入 exe、命令行参数、窗口标题、URL、日志、临时文件。
2. 页面永不明文回显已存密钥（只显示长度占位），且不提供"复制密钥"。
3. WebView2 关闭 DevTools / 右键菜单 / 浏览器快捷键 / 密码保存 / 自动填充；用户数据目录在盘上
   `data\.webview`；导航只允许 `127.0.0.1:<port>`。
4. 启动器自身不保存任何凭据（不做"记住口令"）。
5. 剪贴板只允许"复制命令 / 地址"，不写密钥。

口令仍然在**页面里**输入（现状），启动器不接管口令，也不做原生口令框（见"不做"）。

### 配置页与 Fluent

- 页面仍产出**单文件** `ui/app.html`（零外链）；另建 `src/` 作为可维护的源目录，
  构建脚本把 Fluent 组件、样式与主题内联进 `ui/app.html`。
- 组件库：Fluent UI Web Components v3（`@fluentui/web-components` 3.1.3 + `@microsoft/fast-element`），
  按需引入并 tree-shake，预期内联后体积 +200~400 KB。
- 壳的窗口外观（标题栏、边框、图标区）与页面共用一套 Fluent 2 token，保证"一个应用"的观感。
- 迁移按分区逐块进行，每块都要保持现有行为（接口、字段、任务流不变），不允许"顺手改需求"。

### 构建与仓库

- `build.cmd` 增加启动器编译步骤（走 `tools/build.ps1`），产物：根目录 `dsh-to-go.exe`。
- `third_party/webview2/` 提交三个 DLL（约 0.8 MB）；exe 与编译中间物进 `.gitignore`。
- 新增的界面源目录、构建脚本、验收脚本都进 git；`.scratch/`（规格与棒次文件）进 `.gitignore`。

## 测试决策

- **页面契约**（静态 + DOM 桩，沿用 `tests/` 的 node --test 风格）：
  - 无令牌打开 403、带令牌 200 的老断言继续成立；
  - 页面在"URL 无 token"时向宿主请求令牌，在"URL 有 token"时直接用（浏览器回退不回归）；
  - 产物 `ui/app.html` 里没有 `http(s)://` 外链、没有 CDN、没有明文密钥输入回显。
- **启动器**（真起进程的 e2e，脚本进 `tests/`）：
  - 起 exe → 窗口出现（读窗口标题）→ 本服务返回 200 → 标题/日志/URL 里**没有**令牌；
  - 关窗流程：默认停 dsh 时端口释放；勾"后台继续"时 dsh 仍在；
  - 单实例：第二次启动不新增进程、不换端口；
  - 密钥审计：`data\logs\*`、`data\*.json`、`data\.webview` 里搜不到测试用的哨兵密钥/口令。
- **构建**：`build.cmd` 跑两遍结果一致（幂等）；离线（断网）也能编译出 exe。
- 不测实现细节（不测 C# 内部类、不测 WebView2 内部状态），只测"窗口在不在、服务通不通、有没有泄露"。

## 不做（Out of Scope）

- 启动器接管口令输入（原生口令框）——第二期再议。
- Electron / .NET 8 自包含 / 自带固定版 WebView2。
- 代码签名（SmartScreen 首次运行的提示接受，写进 README 的已知现象）。
- 改 dsh 本体、改上游 `cordis.patch.yml`、改 A/B 槽机制。
- 重写配置页的功能逻辑（迁移只换外观与组件，不改接口与流程）。
