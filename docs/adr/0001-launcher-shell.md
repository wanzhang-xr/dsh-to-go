# ADR 0001：启动器外壳用系统自带 .NET Framework 4.8 + WebView2，而不是 Electron

- 状态：已接受（2026-10-18）
- 决策范围：便携包的**图形入口**（启动器外壳），不涉及配置页内部实现

## 背景

现在日常入口是 `dsh-ui.cmd`：弹一个控制台黑窗，起 `tools/ui-server.js`，再把带 `?token=` 的地址丢给默认浏览器。
它工作正常，但有两个实际问题：

1. 它看起来不像一个应用：黑窗 + 浏览器标签页，用户分不清"关掉哪个才会停"。
2. 浏览器是**共享进程**：扩展、历史、密码管理器、其他标签页都在同一个进程里。配置页本身不碰明文密钥，
   但"把安全管理界面托管在用户日常冲浪的进程里"这件事，与这个项目"拔下来什么都不留"的定位不匹配。

要做一个真正的窗口，就必须回答：**窗口从哪来**。候选只有三条：

| 方案 | 成品体积 | 宿主前提 | 自带浏览器引擎 |
|---|---|---|---|
| .NET Framework 4.8 + WebView2（WinForms，csc 编译） | ~0.8 MB | Win10 1607+ 自带 4.6.2、1903+ 自带 4.8；WebView2 运行时随 Edge 安装 | 否（借 Edge 的） |
| .NET 8 自包含单文件 | ~70 MB | 无（运行时打进 exe） | 否（仍借 WebView2） |
| Electron | ~250 MB | 无 | 是（自带 Chromium + Node） |

## 决策

选 **.NET Framework 4.8 + WebView2**，理由按权重排序：

1. **体积**：0.8 MB 对 70 MB / 250 MB。这个包的卖点是"塞进 U 盘、跟盘走"，启动器体积必须是噪声级。
2. **不需要 .NET SDK**：Windows 自带的 `csc.exe`（`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\`）就能编译，
   构建机不额外装工具链——与 `build.cmd` 现在的"只下载便携 Node"风格一致。
3. **Windows 10/11 的 .NET Framework 是 OS 组件**：Win10 1607 起至少 4.6.2（WebView2 的最低要求），
   1903 起 4.8，Win11 全系 4.8。所谓"Win10 不自带"在本项目支持的目标机上几乎不存在。
4. **拒掉 Electron 的实质理由**：盘上已经有便携 Node；再塞一份 Chromium + Node，等于同一个包里放两套运行时，
   而且 Electron 的入口是 JS——启动器的职责是"隐藏起服务、抓令牌、开窗、管生命周期"，用 JS 做这层没有收益。

## 代价（明确接受）

- **WebView2 不随包分发**：依赖宿主已有 Edge WebView2 运行时。缺失时启动器**不报错退出**，而是回退到
  `dsh-ui.cmd` 的浏览器路径，并说明原因。这是"宁可退化成现在的体验，也不要打不开"。
- **不打包 .NET Framework**：它是 OS 组件，官方安装物 ~70 MB 且需要管理员。既然目标机 100% 自带，
  就不做"把运行时塞进 app"这种收益极低、代价极高的方案；只在检测到缺失时给明确指引。
- **SDK 版本要钉**：最新 WebView2 SDK（1.0.4258.x）在本机运行时 155.0.4283.60 上
  `CoreWebView2Environment.CreateAsync` 会抛 `E_NOINTERFACE`（实测），必须钉 1.0.2903.40，并只用默认环境
  （`EnsureCoreWebView2Async(null)`），用 `CreationProperties.UserDataFolder` 改数据目录。

## 影响

- `third_party/webview2/` 提交三个 DLL（约 0.8 MB）——**这是本仓库第一处入库二进制**，为的是"离线也能构建"。
  exe 本身仍由构建现场生成，不进 git。
- 启动器需要一套自己的验收（真起 exe、读窗口标题、查日志与数据目录），不能用"构建成功"顶替。
